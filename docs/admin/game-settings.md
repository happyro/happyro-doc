# 游戏设置

从“系统设置 → 游戏设置”选择分组，修改后保存，并核对结果和修改记录。只会提交实际修改的字段，不会用打开页面时的旧值覆盖其他管理员修改的无关项；未修改时不会发布。保存和回读期间输入暂时禁用，完成后再继续编辑。游戏内有权限的“冒险工具 → 游戏设置”与后台使用相同服务端规则。

![后台掉落倍率](/images/overview/happyro-admin-settings.png)

## 经验与掉落

经验区分基础与职业经验。掉落按物品类型及普通魔物、Mini、MVP 分别配置，不要把一个类别倍率误当成全局倍率。截图中的 1 倍是拍摄环境当前值，不要求为了匹配图片修改自己的服务器。

## 精炼

精炼成功率倍率默认 1 倍，计算结果向下取整为整数百分比，最高 100%；“精炼必定成功”开启后优先生效，保留倍率但不可编辑。材料、装备条件与装备评级规则不会被免除。

## 传送、召唤与冒险工具

按当前界面调整地图传送、魔物召唤及冒险工具能力。具体权限由服务端统一校验，不能只在客户端显示或隐藏按钮来控制访问。

## 修改记录与持久化

游戏设置页只保留表单。点击页头「查看修改记录」、保存成功提示中的链接，或侧栏「系统设置 → 修改记录」进入独立记录页，核对来源、版本及执行结果。不要同时手工改持久化设置文件和在后台保存同一配置；数据保护见[备份与恢复](/deploy/backup-restore)。

## 上一次修改仍在确认

出现「另一项游戏设置修改尚未完成，请先确认其结果」时，表示上一次请求的最终执行状态尚未确认。先打开修改记录并核对实际配置，不要连续重复提交同一变更。

API 启动后及运行期间会自动检查未完成记录，周期约 10 秒。系统向地图服核对当前值与请求版本，确认迟到的旧请求不能再生效后，已生效的变更标记成功；未生效的变更按当前实际值恢复持久化文件并记录失败，然后允许继续保存。不会为了恢复而重发旧写请求。

若地图服或控制通道不可用、仍有命令运行、或文件被人工改动，系统会保留待确认状态并记录原因，不能保证 10 秒内恢复，也不会无条件覆盖文件。持续等待时按[故障排查](/deploy/troubleshooting#游戏设置一直等待确认)检查服务和日志。历史记录用于核对结果，不是任意版本的一键回滚入口。

## 部署环境变量覆盖

非空玩法环境变量控制的参数不能通过后台保存。当前表单仍可输入，提交时会提示变量名并拒绝整批变更；清空对应变量并重新创建地图服容器或重启原生地图服后恢复后台管理。其他字段与默认值见[环境变量参考](/deploy/environment-variables#玩法与工具权限环境变量)。
