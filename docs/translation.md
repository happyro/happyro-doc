# 关于汉化

HappyRO 的汉化不是简单替换一份语言文件。项目先扫描客户端、服务端和运行资源中的源文件，识别玩家可见文本，再将结果拆分为可追踪、可校验的工作分片，由多个 AI Agent 并行处理，最后统一合并。

AI 翻译可能产生误译、漏译，也可能破坏文件格式或造成内容不一致，因此首次合并结果不能直接发布。当前版本经过多轮格式检查、内容校准、逐值验证和实机修复，后续仍会根据实际游戏体验持续调整。

kRO 客户端资源采用独立流程处理。二进制 LUB 文件先提取为结构化 JSON，只翻译玩家可见文本，合并校验后再编译为对应的 Lua 5.0 或 Lua 5.1 字节码；生成结果还会进行语义回环和客户端实机验证，确保键名、索引、控制流与运行行为没有变化。官方输入资源始终保持只读。

`docs/translation/zh-cn/` 仅保存已完成翻译批次的历史记录，不再用于当前翻译或发布。产品翻译直接维护在 `repos/happyro-client`、`repos/happyro-server` 和 `localization/client/data`，不得从归档目录回写。
